## Project Context (Read First)

This file is a supplement. The canonical project context is at **`WMS-PLATFORM-OVERVIEW.md`** which documents:
- Tech stack (React 19, TanStack Router, TanStack Query, Zustand, shadcn/ui, Tailwind CSS)
- 41 existing Prisma models and their relationships
- 48+ existing API controllers (Web + RF)
- 11 fully implemented P2 modules
- API prefix convention: `/api/v1/wms/web/...`
- All existing route paths and feature modules

Key patterns this UI project follows:
1. **Feature structure:** `src/features/{domain}/` → `components/`, `data/`, `pages/`, `index.tsx`
2. **Route structure:** `src/routes/_authenticated/{section}/route.tsx` (layout) + `{section}/{page}.tsx` (leaf)
3. **Page shell:** `<Header>` + `<Main>` wrapping a feature component
4. **Data tables:** `@tanstack/react-table` with `DataTableToolbar`, `DataTablePagination`, `DataTableColumnHeader`, `useTableUrlState`
5. **Dialogs:** shadcn `Dialog` with `react-hook-form` + `zod` validation
6. **Queries:** `@tanstack/react-query` with `safeArray<T>()`/`safeTotal()` helpers
7. **Toasts:** `sonner`
8. **API client:** Auto-generated by orval at `src/lib/api/wms-api/wms-web/wms-web.ts`
9. **Types:** `src/lib/types/wms-api/` — one file per DTO/params type
10. **Navigation:** `src/components/layout/data/sidebar-data.ts`
11. **Assets (icons):** `lucide-react`

## Coding Standards Quick Reference

For detailed patterns (query hooks, dialogs, tables, error/loading/empty states, page shells, route layouts, status badges, toasts, URL state, delete confirmations, forms, API error handling), read lines 50–200 of the **Phase 0** section in the previous version of this document (preserved below) or refer to the existing feature implementations listed in each phase under "Patterns to Follow."

Critical rules:
1. **Always** use `safeArray<T>()` + `safeTotal()` helpers for API response normalization
2. **Always** use `useTableUrlState` for table pagination/filter state
3. **Always** use `sonner` toasts for success/error feedback
4. **Always** use `useQueryClient().invalidateQueries()` on mutation success
5. **Always** handle loading (Skeleton), error (text-destructive + retry), and empty states
6. **Always** wrap mutations in try/catch with toast.error fallback
7. **Always** use Zod schemas via `@hookform/resolvers/zod`
8. **Always** use the `@/` path alias for project imports
9. **Always** add breadcrumb labels to new route files
10. **Always** consume `facilityId` from context/URL, never hardcode
